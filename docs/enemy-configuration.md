# 敌人配置

“敌人”是独立工作区，包含敌人分类、特殊敌人和特殊敌人权重。训练 NPC 位于“其他”。每个赛季分别记忆两个工作区最近访问的子页。

## 编辑方式

敌人分类左侧列出分类与数量，右侧编辑当前分类。窄窗口使用分类选择器。搜索只过滤显示，序号仍对应原始位置，编辑和删除均作用于该位置。新增会清空搜索并聚焦新条目；保存保持列表原始顺序。

特殊敌人维护主敌人、类别、单体随机权重、前半场标记，以及附加普通和精英敌人。特殊敌人权重维护类别层面的 `count` 与 `weight`，与单体随机权重分别保存。

## 当前应用链路

以下结论依据 2026-10-22 的编辑器、服务器及客户端源码检查：

- 编辑器以原有赛季字段保存和导出。`specialEnemyInfoDict` 在目录模式下拆分存储；`enemyInfoDict` 和 `specialEnemyRandomTypeDict` 位于 `project.json.constFields`。界面调整不迁移数据。
- 服务器 `src/season-resolution.ts` 校验特殊敌人记录，`src/connection.ts` 通过赛季响应下发有效数据。
- 服务器 `src/data-generator.ts` 的 `generateMonsterKeys()` 从 FLY、TIMES、ELEMENT、DOT、INVISIBLE、REFLECTION 六类中等概率选三类。`generateLoadingRoundEnemies()` 按代码规则生成初始回合类别，没有读取配置中的类别 `count / weight`，也没有直接按特殊敌人条目的单体权重选择主敌人。
- 客户端 `src/client-resources.ts` 收集分类成员、特殊敌人主键及两类附属敌人，纳入敌人资源计划；FLY 参与默认飞行属性判断，已有原生属性与显式资源配置还会影响最终属性。
- 客户端 `src/autochess-gamemode.ts` 保留这三份字段，将赛季转换为原生赛季表，并登记敌人属性。PC 和 PE 走共同业务代码。
- 服务器还会接收加载阶段上报的实际回合敌人信息，保存用于后续战斗同步。

因此这些配置确实进入客户端配置与资源使用链路。原生抽怪对单体权重、前后半场标记、附属敌人和类别权重的具体运算，不能仅由当前脚本源码完全确认；实际概率和出怪结果需要运行验证。资源登记本身也不等于该敌人一定会在对局中出现。

PC JSON、PE JSON 的敌人字段及服务器协议保持原有契约。

## 本次界面验收

使用独立本地接口和临时赛季副本，已检查分类长短悬殊、120 条列表、空分类、长 ID、窄屏选择器、筛选后的编辑与删除、新增聚焦、特殊敌人增删改与附属敌人编辑，以及两工作区和两个赛季的子页记忆、前进后退及历史名称。

保存重载后检查编辑值；逐字段比对确认只包含预期编辑，第二个赛季保持原样。PC、PE 和目录导出的三份敌人字段一致，旧导航标识兼容检查通过。临时接口未提供多人协作连接，多用户联测及真实对局抽怪行为尚未验证。测试代码和数据留在本机临时目录。
