# 局内奖励池

入口：奖励 → 局内奖励池。内置池目录和实际候选预览不会自动向赛季写入覆盖。

## 覆盖与回退

游戏服务器使用 `runtimeConfig.rewardPools: Record<string, { chessId: string; value: number }[]>`。
赛季池存在有效正权重候选时覆盖同名默认池；未声明、空数组、全零权重或条目全部失效时回退同名默认池。没有可用同名池则不发奖励。
部分无效条目由服务器逐行诊断，其余有效条目仍参与抽取。权重按相对比例、有放回抽取，数量与触发时机由效果决定。

“移除覆盖 / 恢复默认”同时删除名单和规则。仍被引用的自定义池不能删除；内置池可以恢复默认。
引用检查包含效果和驻扎的 `pool`、`pool1…pool6`、`max_pool`，点击引用可跳转。

## 内置配方

| 池名 | 配方 |
| --- | --- |
| pool_chess_glady | 斯卡蒂、幽灵鲨、安哲拉；无安哲拉时深巡 |
| pool_equip_rockr、pool_equip_vict | 维式重锤及灼燃、坚固、加速、战栗四种强化重锤 |
| pool_equip_pepe | 盟约之币、萨尔贡浓茶、黄沙罗盘；权重 100、100、10 |
| pool_equip_normal、pool_equip_kathe、pool_equip_narant | 全部非金色 EQUIP，含隐藏和未上架条目 |
| pool_equip_shop_1 | 非隐藏、等级 ≤ 1 的商店装备，排除强化维式重锤和突变细胞 |
| pool_char_pinus | 灰毫、野鬃、远牙 |
| pool_char_later | 非隐藏、等级 ≥ 4 的拉特兰商店干员的金色版本 |
| pool_chess_shop_1_reward、pool_chess_shop_2_reward、pool_chess_shop_4_reward、pool_chess_shop_5_reward | 非隐藏且分别为 1、2、4、5 级的商店干员 |

配方只使用赛季内存在的实体。默认权重为 1。默认配方的实体 ID 依据游戏服务器映射，显示名沿用编辑器名称表。
`pool_equip_shop_1` 的默认全员装备奖励入口还受商店剩余库存与供应概率约束；有效赛季覆盖改用声明权重。预览列出的基础权重不代表动态库存下的最终概率。其他调用方的禁用干员、特殊招募等筛选继续生效。

## 固定名单和动态规则

固定名单支持按中文名或 ID 搜索干员、装备、法术及金色版本，编辑每项权重。复制默认候选得到当前赛季的固定快照。

动态规则保存于 `runtimeConfig.rewardPoolRules`。同名规则优先于保存的生成名单，按当前赛季数据实时预览，保存或导出前重新生成 `rewardPools`。
规则可转换为固定名单，此操作删除规则并保留当前生成结果。

```json
{
  "source": "shop",
  "kind": "equip",
  "quality": "normal",
  "visibility": "visible",
  "levels": [3],
  "bondIds": [],
  "excludeIds": [],
  "weight": 1,
  "weightOverrides": {}
}
```

- `source`：`all` 全部实体，`shop` 有对应商店条目的实体。
- `kind`：`char` 干员、`equip` 装备、`magic` 法术、`all` 全部。
- `quality`：`normal`、`golden`、`all`，使用实体实际金色标记和配对关系，不根据 ID 后缀推测。
- `visibility`：`visible` 非隐藏商店条目、`hidden` 隐藏商店条目、`all` 不限，包含未上架实体。
- `levels`：非负整数列表，空列表不限；等级取普通/金色关联的商店记录，缺少等级的实体不匹配等级条件。
- `bondIds`：干员的盟约任一匹配，空列表不限；其他类型不能指定盟约。
- `excludeIds`：排除的棋子 ID。
- `weight`：统一默认权重；`weightOverrides` 按棋子 ID 覆盖权重。权重必须为有限非负数，0 不参与抽取。

各条件取交集，多选值取并集。每个棋子最多出现一次，生成顺序稳定。不在当前候选中的权重覆盖仍保留，候选重新进入时恢复生效。
非法规则保留在编辑数据中供修复，但阻止保存/导出并报告字段。合法的空结果允许保存，按同名默认池回退。

## 保存与平台

目录项目将规则及名单保存在 `project.json.constFields.runtimeConfig`；JSON、在线保存和协作持久化保留规则。
PC JSON 按完整数据生成。PE JSON 先执行现有平台筛选，再重新生成规则名单，并删除固定名单中被该次平台筛选移除的实体，规则原文保留。
在线游戏服务器校验使用重新生成后的名单，避免预览与提交内容不一致。

游戏服务器解析器 10 起支持“无有效候选回退”，旧服务器的空池仍表示不发奖励。规则无需游戏客户端执行，PC/PE 使用现有奖励协议。
部署顺序为先更新游戏服务器，再发布编辑器。本次实现仅本地构建和提交，发布按用户要求执行。

- 浏览器使用本地验收副本和模拟接口验证新增、权重编辑、保存后刷新、全零回退、恢复默认以及 PC/PE 下载；未写入线上赛季，线上数据库与多人协作仍需部署后验证。

- 编辑器前后端构建、游戏服务器 TypeScript 检查通过；真实对局由用户验收。
